# 小说正文乱码与质量扫描器

## 扫描内容

`runtime/text-quality.js` 是不联网的正文检测引擎；`runtime/source-test-runner.js` 在书源四阶段测试中调用它，对实际抓取的章节正文进行抽样扫描。

检测项目：
- Unicode 替换字符 `�`。
- 常见 UTF-8 错位痕迹（`Ã`、`Â`、`â€`、`ä¸`、`å`、`æ` 等）。
- 常见错误替换文本（`锟斤拷`、`烫烫烫`、`屯屯屯`）。
- 错误或未闭合 HTML 实体残留。
- 私用区字符及异常控制字符。
- 空章节、过短章节和完全重复章节。

## 在书源测试中的用法

每个书源通过受限宿主执行搜索、详情、目录和正文测试。默认抽样前 5 章，最多 20 章。正文只在测试运行内存中检查；报告只保留章节标题、字符长度、异常类型和数量，不保存章节正文。

测试报告会区分：
- `normal`：未发现当前规则覆盖的异常。
- `suspect`：发现乱码迹象、异常字符或重复正文。
- `review`：正文为空或过短，需要人工判断。

任何疑似问题都不会自动修改小说内容，也不会单凭扫描结果启用书源。

## 局限

启发式扫描不能识别所有语义错字、OCR 错字、漏段或错序。部分乱码如果已经被错误转换成看似正常的汉字，纯文本模式可能无法识别；要进一步定位字符集解码错误，需要宿主同时提供原始响应字节、HTTP charset 与解码结果。繁体字、异体字、生僻字不会单因不常见而被判为乱码。
